# Telegram-бот техподдержки на Python

## Структура проекта

Точка запуска остаётся прежней — `python support_bot.py`. Код разнесён по назначению:

- `bot/config.py` — переменные окружения, настройки и общие зависимости;
- `bot/database.py` — схема и операции SQLite, пользователи, баланс и рефералы;
- `bot/xui.py` — клиент API 3x-ui и форматирование данных панели;
- `bot/tickets.py` — обращения, заявки, клавиатуры и общая доменная логика;
- `bot/handlers.py` — Telegram-команды, callback-кнопки и обработчики сообщений;
- `support_bot.py` — минимальная точка запуска.

Бот принимает сообщения от пользователей, передаёт их администраторам, позволяет отвечать пользователям, закрывать обращения, блокировать пользователей, делать рассылки и управлять администраторами.

## Возможности

- Пользователь пишет сообщение в бот — администраторы получают обращение.
- Поддерживаются текст, фото, документы, видео, голосовые и другие типы сообщений.
- Админ может ответить:
  - кнопкой `Ответить` под обращением;
  - командой `/reply ID текст`;
  - обычным ответом в Telegram на сообщение обращения.
- Обращения сохраняются в SQLite.
- Есть команды блокировки, статистики, списка пользователей, рассылки и управления администраторами.
- Для заявок на продление можно принимать оплату вручную по реквизитам или через Telegram Stars.

## Установка

1. Установите Python 3.10 или новее.
2. Создайте бота через `@BotFather` и получите токен.
3. Скачайте проект и установите зависимости:

```bash
pip install -r requirements.txt
```

4. Скопируйте `.env.example` в `.env`:

```bash
copy .env.example .env
```

На Linux/macOS:

```bash
cp .env.example .env
```

5. Заполните `.env`:

```env
BOT_TOKEN=токен_бота
ADMIN_IDS=ваш_telegram_id
SUPER_ADMIN_ID=ваш_telegram_id
DB_PATH=support_bot.sqlite3
```

6. Запустите бота:

```bash
python support_bot.py
```

### Как обновить кнопки у старых пользователей

Нижняя клавиатура Telegram обновляется только вместе с новым сообщением от бота. Поэтому пользователи, которые уже открывали бота раньше, могут не увидеть новые кнопки сразу после обновления кода.

После запуска новой версии нажмите в админском меню кнопку:

```text
🔄 Обновить меню
```

или выполните команду:

```text
/updatemenus
```

Бот отправит всем известным пользователям новое сообщение с актуальными кнопками меню.

## Продление подписок 3x-ui

В проект добавлена интеграция с API панели 3x-ui. Для 3x-ui Node бот работает через новый раздел **Clients API**: продлевает именно глобальную подписку клиента, а не запись клиента внутри конкретного inbound.

Теперь команда `/renew EMAIL DAYS` использует endpoint:

```text
/panel/api/clients/bulkAdjust
```

Это важно для 3x-ui Node: клиент может быть прикреплён к нескольким inbounds, но продление подписки выполняется на уровне клиента по email. Бот не перезаписывает весь объект клиента, а именно добавляет нужное количество дней к подписке.

### Логика заявки на продление

1. Клиент нажимает кнопку `🔄 Продлить подписку`.
2. Бот спрашивает количество месяцев.
3. После ввода срока бот показывает клиенту две кнопки выбора оплаты:
   - `P2P(Перевод)`;
   - `⭐️ Tg Stars`.
4. Только после выбора способа оплаты бот создаёт **новое обращение** и присваивает ему новый номер.
5. Админ видит выбранный клиентом способ оплаты в карточке заявки и в списке заявок.
6. Если клиент выбрал `P2P(Перевод)`, всё работает как раньше: админ отправляет реквизиты, клиент нажимает `✅ Платёж выполнен`, после проверки оплаты админ нажимает `✅ Продлить по заявке`.
7. Если клиент выбрал `⭐️ Tg Stars`, бот сам выставляет клиенту счёт. Сумма считается автоматически: `количество месяцев * STARS_PRICE_PER_MONTH`.
8. После успешной оплаты Stars бот пытается автоматически найти подписку клиента по Telegram ID из поля `tgId` в 3x-ui. Если клиент найден, бот сам продлевает подписку, закрывает обращение и отправляет клиенту уведомление об успешном продлении.
9. Если после оплаты Stars бот не смог найти клиента по `tgId`, админ получает уведомление, открывает заявку и указывает email вручную через кнопку `✍️ Ввести email/дни вручную` или `📧 Продлить по email без привязки`.

Если Telegram ID не найден в панели 3x-ui, в карточке заявки есть запасная кнопка `✍️ Ввести email/дни вручную`. Также можно использовать команды `/renewticket TICKET_ID [DAYS]`, `/renew EMAIL DAYS TICKET_ID` или `/renewuser USER_ID DAYS TICKET_ID`, если нужно продлить вручную и всё равно отправить уведомление клиенту по номеру обращения.

### Настройка `.env`

Добавьте в `.env` настройки панели:

```env
# Адрес панели. Если в 3x-ui задан секретный URI Path, добавьте его в конец.
# Пример: https://example.com:2053/randompath
XUI_BASE_URL=https://example.com:2053

# Лучше использовать API-токен из Settings -> Security -> API Token
XUI_API_TOKEN=

# Если API-токен не используется, бот попробует войти через /login
XUI_USERNAME=admin
XUI_PASSWORD=your_panel_password

# Если SSL-сертификат самоподписанный, можно поставить false
XUI_VERIFY_SSL=true
XUI_TIMEOUT=20

# Для 3x-ui Node оставьте clients_api
XUI_RENEW_MODE=clients_api

# Способ продления в Clients API:
# bulk_adjust — основной режим: /panel/api/clients/bulkAdjust, добавляет дни к подписке.
# update — запасной режим: /panel/api/clients/update/{email}, выставляет expiryTime.
XUI_CLIENTS_RENEW_METHOD=bulk_adjust

# Сколько клиентов показывать на одной странице команды /clients
XUI_CLIENTS_PER_PAGE=10

# Показывать уникальных клиентов, а не копии по каждому inbound
XUI_GROUP_CLIENTS_BY_EMAIL=true

# На сколько дней продлевать, если в команде не указать DAYS
XUI_DEFAULT_RENEW_DAYS=30

# Настройки кнопки «Продлить подписку» у клиента
XUI_DAYS_PER_MONTH=30
XUI_MAX_RENEW_MONTHS=24

# Обычно Clients API применяет изменения сам. Включайте true только если нужно перезапускать Xray после продления.
XUI_RESTART_XRAY_AFTER_RENEW=false

# Telegram Stars как дополнительный способ оплаты
STARS_PAYMENTS_ENABLED=true
STARS_MIN_AMOUNT=1
STARS_MAX_AMOUNT=100000
STARS_PRICE_PER_MONTH=250
STARS_INVOICE_TITLE=Продление подписки
STARS_INVOICE_DESCRIPTION=Оплата продления подписки через Telegram Stars
```

Если используете API-токен, поля `XUI_USERNAME` и `XUI_PASSWORD` можно оставить пустыми.

`XUI_MAIN_INBOUND_ID` больше не нужен для обычного режима 3x-ui Node. Он нужен только для старого режима `XUI_RENEW_MODE=legacy_inbound`.

### Оплата Telegram Stars

Клиент выбирает `⭐️ Tg Stars` сам при создании заявки. Бот сразу выставляет счёт в Telegram Stars.

Порядок работы:

1. Клиент нажимает `🔄 Продлить подписку`.
2. Указывает количество месяцев.
3. Выбирает `⭐️ Tg Stars`.
4. Бот создаёт обращение и отправляет счёт.
5. После успешной оплаты Telegram присылает боту событие `successful_payment`.
6. Если у клиента в 3x-ui заполнен `tgId`, бот автоматически продлевает подписку, закрывает обращение и уведомляет клиента.
7. Если `tgId` не найден, бот уведомляет админов, и админ вручную указывает email в заявке.

Сумма счёта рассчитывается автоматически:

```text
сумма Stars = количество месяцев * STARS_PRICE_PER_MONTH
```

Для Telegram Stars используется валюта `XTR` и пустой `provider_token`, отдельный платёжный провайдер не нужен.

Если способ оплаты `P2P(Перевод)`, логика остаётся ручной: админ отправляет реквизиты, клиент подтверждает оплату кнопкой `✅ Платёж выполнен`, затем админ продлевает подписку.

### Список всех клиентов 3x-ui

Команда:

```text
/clients
/clients 2
```

Сначала бот пробует получить клиентов через новый endpoint `/panel/api/clients/list`. Если он недоступен на старой версии панели, бот fallback-режимом читает `/panel/api/inbounds/list` и группирует клиентов по `email`.

В списке отображаются:

- email клиента;
- количество attached inbounds;
- статус клиента;
- дата окончания `expiryTime`;
- использованный трафик и лимит;
- `tgId`, если он указан у клиента.

Количество клиентов на одной странице регулируется настройкой `XUI_CLIENTS_PER_PAGE` в `.env`.

### Как работает продление

1. Бот получает текущую глобальную запись клиента через `/panel/api/clients/get/{email}`.
2. Отправляет запрос в `/panel/api/clients/bulkAdjust` с телом вида `{"emails": ["EMAIL"], "addDays": DAYS, "addBytes": 0}`.
3. 3x-ui сам добавляет дни к подписке клиента.
4. Бот повторно читает клиента и показывает новую дату окончания.

В этом режиме бот не отправляет поле `id` и не перезаписывает весь объект клиента, поэтому не возникает ошибка `cannot unmarshal number into Go struct field Client.id of type string`.

## Баланс и реферальная программа

У клиента в меню есть кнопки `💰 Баланс` и `👥 Рефералы`.

- Баланс ведётся в Stars-эквиваленте. Им можно оплатить оформление или продление: пользователь сначала выбирает срок, затем `💰 С баланса`.
- Пополнение через Telegram Stars зачисляется автоматически.
- Для P2P и криптовалюты пользователь создаёт заявку на сумму, переводит деньги и нажимает `✅ Я перевёл`. Администратор получает кнопку `✅ Подтвердить и зачислить`; до её нажатия баланс не меняется.
- Реферальная ссылка имеет вид `https://t.me/<имя_бота>?start=ref_<telegram_id>`. При первом запуске по ней пользователь навсегда становится рефералом пригласившего.
- После каждого подтверждённого пополнения реферала пригласившему автоматически начисляется `REFERRAL_PERCENT` процентов (по умолчанию 25%) на баланс.
- Продление с баланса доступно, когда подписка привязана к Telegram ID. Если существующая подписка не привязана, администратор должен выполнить `/linksub USER_ID EMAIL`. Новому пользователю при оплате с баланса бот создаёт клиента в заранее заданных `XUI_NEW_CLIENT_INBOUND_IDS`.

Добавьте в `.env`:

```env
BALANCE_PRICE_PER_MONTH=250
REFERRAL_PERCENT=25
CRYPTO_PAYMENT_DETAILS=USDT TRC20: T...your_wallet
```

### Меню клиента

У обычного пользователя появляются кнопки:

```text
🔄 Продлить подписку
🆘 Обращение
```

Как работает:

Настройки срока для клиентской кнопки:

```env
XUI_DAYS_PER_MONTH=30
XUI_MAX_RENEW_MONTHS=24
```

- `🔄 Продлить подписку` — бот сначала спрашивает у клиента желаемое количество месяцев. После ответа клиента бот создаёт обращение и отправляет администраторам заявку на продление с указанным сроком. Каждая такая заявка всегда создаёт новое обращение с новым номером. Если Telegram ID клиента указан в панели 3x-ui в поле `tgId`, бот сам найдёт email подписки. Сначала админ отправляет реквизиты кнопкой `💳 Отправить реквизиты`, затем клиент может нажать `✅ Платёж выполнен`, и только после этого админ продлевает подписку кнопкой `✅ Продлить по заявке`. После продления бот закрывает обращение и отправляет клиенту сообщение об успешном продлении по этому номеру обращения.
- `🆘 Обращение` — бот просит пользователя описать проблему. Дальше сообщение передаётся администраторам как обычное обращение.

## Обновление: подтверждение оплаты клиентом

Добавлено:

- у клиента в меню остаются только две кнопки: `🔄 Продлить подписку` и `🆘 Обращение`;
- клиентам больше не показываются подсказки по командам;
- после отправки реквизитов через кнопку `💳 Отправить реквизиты` клиент получает inline-кнопку `✅ Платёж выполнен`;
- при нажатии на `✅ Платёж выполнен` админам приходит уведомление с номером обращения и кнопками управления заявкой;
- подтверждение оплаты записывается в историю обращения как событие `payment_done`;
- в карточке заявки и в списке заявок отображается статус оплаты.

Сценарий работы:

1. Клиент нажимает `🔄 Продлить подписку`.
2. Клиент указывает количество месяцев.
3. Создаётся новое обращение-заявка на продление.
4. Админ нажимает `💳 Отправить реквизиты` и отправляет клиенту реквизиты/сумму.
5. Только после отправки реквизитов появляются кнопки продления.
6. Клиент нажимает `✅ Платёж выполнен`.
7. Админ получает уведомление, проверяет оплату и нажимает `✅ Продлить по заявке`.
8. После успешного продления обращение закрывается, а клиент получает уведомление об успешном продлении.


## Обновление: защита от преждевременного продления

Теперь админ не может сразу продлить заявку после её создания. В новой заявке сначала показывается только кнопка:

```text
💳 Отправить реквизиты
```

После нажатия админ отправляет клиенту реквизиты и сумму. Только после этого в заявке появляются кнопки:

```text
✅ Продлить по заявке
✍️ Ввести email/дни вручную
```

Если админ попробует выполнить `/renewticket TICKET_ID` до отправки реквизитов, бот не продлит подписку и попросит сначала отправить реквизиты. Это защищает от случайного продления до оплаты.

## Обновление: привязка Telegram ID в панели 3x-ui и продление без привязки

Добавлена логика для случаев, когда админ вручную указывает email клиента в заявке на продление.

Обычный ручной сценарий:

1. Админ открывает заявку на продление.
2. Нажимает `✍️ Ввести email/дни вручную`.
3. Вводит, например:

```text
client_email 30
```

После этого бот сначала записывает Telegram ID пользователя в поле `tgId` клиента в самой панели 3x-ui через Clients API, затем сохраняет локальную привязку в базе бота и только после этого продлевает подписку.

Если нужно продлить клиента по email, но не создавать привязку, используйте кнопку:

```text
📧 Продлить по email без привязки
```

В этом режиме бот попросит ввести `email days`, например:

```text
client_email 30
```

Подписка будет продлена, клиент получит уведомление по номеру обращения, но email не будет сохранён в базе бота и `tgId` в панели 3x-ui не будет изменён.

Новая настройка `.env`:

```env
XUI_SYNC_TGID_TO_PANEL_ON_LINK=true
```

Если поставить `false`, команда `/linksub` и ручной ввод email в заявке будут создавать только локальную привязку в базе бота, без записи `tgId` в панель 3x-ui.

## Исправление tgId

В этой версии исправлена отправка `tgId` в панель 3x-ui: значение передаётся числом `int64`, а не строкой. Это устраняет ошибку вида:

```text
json: cannot unmarshal string into Go struct field Client.tgId of type int64
```

## Обновление: отклонение заявки на продление

В карточку заявки на продление добавлена кнопка:

```text
❌ Отклонить заявку
```

При нажатии бот:

1. переводит заявку в статус `rejected`;
2. закрывает связанное обращение;
3. добавляет событие в историю обращения;
4. отправляет клиенту уведомление, что заявка на продление отклонена.


### Исправление продления просроченных подписок

Добавлена настройка:

```env
XUI_RENEW_EXPIRED_FROM_NOW=true
```

Если подписка клиента уже истекла, бот выставляет новый срок от текущего момента: `сейчас + DAYS`. Если подписка ещё активна, срок продлевается от текущей даты окончания.

## Обновление: оформление новой подписки

Добавлена клиентская кнопка:

```text
🆕 Оформить подписку
```

Сценарий работы:

1. Клиент нажимает **🆕 Оформить подписку**.
2. Указывает количество месяцев.
3. Выбирает способ оплаты:

```text
P2P(Перевод)
⭐️ Tg Stars
```

### P2P(Перевод)

Если клиент выбрал P2P, бот создаёт новое обращение и заявку на оформление подписки. Админ видит заявку, отправляет реквизиты, клиент нажимает **✅ Платёж выполнен**, после чего админ нажимает **✅ Создать клиента**.

Бот создаёт клиента в 3x-ui, записывает `tgId`, сохраняет локальную привязку и закрывает обращение. Email новой подписки создаётся автоматически и всегда уникален: после `_` используется текущий timestamp в миллисекундах, например `client_1783161234567`.

### Telegram Stars

Если клиент выбрал **⭐️ Tg Stars**, бот автоматически выставляет счёт. После успешной оплаты бот сам создаёт клиента в 3x-ui, записывает `tgId`, сохраняет локальную привязку и закрывает обращение.

Если автоматическое создание не удалось, админ получит уведомление и сможет открыть заявку, нажать **✍️ Ввести email/дни вручную** и указать другой email.

### Настройки новых клиентов

Добавлены настройки `.env`:

```env
XUI_NEW_CLIENT_INBOUND_IDS=1,2,3
XUI_NEW_CLIENT_TOTAL_GB=0
XUI_NEW_CLIENT_LIMIT_IP=0
XUI_NEW_CLIENT_EMAIL_PREFIX=client
# Email создаётся как PREFIX_timestamp, например client_1783161234567
XUI_NEW_CLIENT_FLOW=
XUI_NEW_CLIENT_GROUP=
XUI_NEW_CLIENT_COMMENT=Создано ботом техподдержки
```

`XUI_NEW_CLIENT_INBOUND_IDS` лучше заполнить явно. ID inbound можно посмотреть командой:

```text
/inbounds
```

Если `XUI_NEW_CLIENT_INBOUND_IDS` не указан, бот попробует сам получить список подходящих inbound через `/panel/api/inbounds/options` или `/panel/api/inbounds/list`.

## Сообщения и ссылка после создания нового клиента

После нажатия админом кнопки `✅ Создать клиента` бот теперь:

1. создаёт клиента в 3x-ui;
2. скрывает кнопку создания клиента в карточке заявки;
3. отправляет клиенту email/логин, дату окончания и ссылку подписки;
4. пересылает клиенту заранее заданные админом сообщения, например инструкцию по подключению.

Чтобы заранее задать эти сообщения:

```text
/submessages
```

Затем нажмите `📝 Записать заново` или используйте команду:

```text
/setsubmessages
```

После этого отправьте боту все сообщения, которые нужно выдавать новым клиентам, по порядку. Можно отправлять текст, фото, документы и другие сообщения. Когда закончите, напишите:

```text
/done
```

Очистить сохранённые сообщения можно командой:

```text
/clearsubmessages
```

Ссылка подписки формируется из `subId`, который возвращает 3x-ui при создании клиента. По умолчанию используется шаблон:

```env
XUI_SUBSCRIPTION_LINK_TEMPLATE={base}/sub/{subId}
```

Если у вас отдельный адрес для подписок, укажите его в `.env`:

```env
XUI_PUBLIC_SUBSCRIPTION_BASE_URL=https://your-domain.example
```

## Обновление: подтверждение создания клиента и отправка материалов

После нажатия админом кнопки **✅ Создать клиента** бот теперь:

1. создаёт клиента в 3x-ui;
2. скрывает кнопку **✅ Создать клиента** в сообщении заявки;
3. отправляет админу отдельное сообщение об успешном создании клиента;
4. закрывает обращение;
5. отправляет клиенту сообщение об успешном оформлении;
6. отдельно отправляет клиенту ссылку подписки;
7. пересылает клиенту заранее сохранённые сообщения/инструкции, заданные через `/setsubmessages` или меню `/submessages`.

Если ссылка подписки не формируется, проверьте настройки:

```env
XUI_PUBLIC_SUBSCRIPTION_BASE_URL=
XUI_SUBSCRIPTION_LINK_TEMPLATE={base}/sub/{subId}
```
