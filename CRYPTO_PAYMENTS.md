# Автоматические криптопополнения

Платёжная служба использует ту же SQLite-базу, что и Telegram-бот. Бот сохраняет счёт в рублях и показывает сумму, сеть и адрес. Отдельный процесс проверяет блокчейны, зачисляет рубли и уведомляет плательщика. Выставлять счета можно только после синхронизации службы с сетью.

## Конфигурация

1. В активированном окружении бота установите зависимости командой `pip install -r requirements.txt`.
2. Скопируйте `crypto-payments.example.json` в `crypto-payments.json`. Укажите свои RPC, реквизиты и курс в рублях за одну единицу актива. Значения курса задаются вручную, а сумма фиксируется при создании счёта. Удалите из `rates_rub` способы, которые пока не готовы принимать оплату.
3. Добавьте в `.env` абсолютный путь, например `CRYPTO_PAYMENTS_CONFIG=/opt/tg_bot_shop/crypto-payments.json`. Ограничьте чтение файла конфигурации пользователем обоих процессов, если в нём есть RPC-пароль.
4. Запустите `python -m bot.crypto_worker` из каталога бота и перезапустите бота. В личном чате откройте **Баланс → Пополнить криптовалютой**. Пункт **Мои криптосчета** показывает последние счета и состояние каждого из них.

## Адреса и сети

| Сеть | Как подготовить | Какие переводы распознаются |
| --- | --- | --- |
| TON | Свой индексатор с TON Center API v3 и доступным `runGetMethod`. Укажите свой активированный кошелёк TON Mainnet. | GRAM и официальный USDT. При каждом переводе необходимо передать комментарий из счёта. Для USDT кошелёк должен отправить стандартное уведомление jetton получателю. |
| TRON | Solidity HTTP API собственной ноды TRON Mainnet и пул свежих адресов, ключи которых есть у владельца. | События `Transfer` официального USDT TRC-20 в подтверждённых блоках. |
| Bitcoin | Собственная нода и загруженный watch-only кошелёк Bitcoin Core Mainnet. Импортируйте адреса из пула как наблюдаемые, либо импортируйте публичный дескриптор с подходящим диапазоном. В URL укажите `/wallet/ИМЯ`. | Входящие on-chain переводы после настроенного числа подтверждений. |
| Ethereum | Своя нода Ethereum Mainnet (execution и consensus) и пул свежих ETH-адресов. | Прямые переводы ETH на адрес счёта в финализированных блоках. Переводы внутри смарт-контрактов в этот сценарий не входят. |

Службе нужны публичные адреса. Seed-фразы и ключи расходования держите в кошельках, из которых потом сможете вывести средства. Узлы и их RPC должны быть на приватном интерфейсе или доступны службе через закрытую сеть.

BTC, ETH и TRON получают отдельный адрес на каждый счёт. Адрес закрепляется в базе навсегда, чтобы поздний перевод не попал на чужой счёт. Пополняйте пулы новыми адресами. Пул Bitcoin должен оставаться доступным в используемом watch-only кошельке. Кошелёк TON общий для GRAM и USDT, счета различаются уникальным комментарием. Смена адреса TON требует сверки старых счетов и отдельной миграции.

## Служба systemd

Пример для `/etc/systemd/system/telegram-crypto-payments.service`. Подставьте пользователя службы и путь к текущей установке бота и её виртуальному окружению.

```ini
[Unit]
Description=Telegram shop blockchain payment worker
Wants=network-online.target
After=network-online.target

[Service]
User=bot
WorkingDirectory=/opt/tg_bot_shop
ExecStart=/opt/tg_bot_shop/venv/bin/python -m bot.crypto_worker
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now telegram-crypto-payments
sudo journalctl -u telegram-crypto-payments -n 60 --no-pager
sudo systemctl restart telegram-support-bot
```

После изменения конфигурации нод, кошельков, токена бота или пути к базе перезапустите оба процесса. Убедитесь, что `DB_PATH` у них совпадает. При первом запуске служба начинает следить с текущей подтверждённой позиции сети. Новые счета доступны после успешного сканирования. Перед отключением сети или актива сверьте выставленные по ним счета.

## Зачисление и спорные переводы

Подтверждённые поступления на один счёт складываются. Когда суммы, полученной в срок, достаточно, начисляется ровно сумма счёта в рублях. Идентификаторы поступлений и запись о зачислении хранятся в SQLite, поэтому повторная обработка блока или перезапуск не дублируют зачисление. Подтверждения могут прийти после истечения счёта, если сам перевод относится к его сроку действия.

Недоплата ниже суммы счёта, перевод за его пределами, неверная сеть, отсутствие комментария TON или переплата сверх суммы требуют сверки по номеру счёта и блокчейну. Излишек автоматически не зачисляется. Перед открытием способа оплаты клиентам проведите небольшой контрольный перевод в каждой подключённой сети.
